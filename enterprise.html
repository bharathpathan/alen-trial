Data stays in your network

ALEN runs on developer machines; the optional server runs on your infrastructure. Choose on-prem models and nothing reaches a third party.

  • Private folders only local models can read
  • Data classes route sensitive files away from cloud models
  • Secret redaction on every request

Central, signed policy

Write rules once on the server. Each machine checks the signature (Ed25519); a tampered or stale copy blocks changes instead of being ignored.

  • What agents may run, read and change
  • Which models may see which data
  • MCP servers and tools allowed

People and approvals

Single sign-on with your OIDC provider, roles per team, and approvals that need more than one person for risky changes.

  • Tenants isolated in the database
  • Secrets in HashiCorp Vault or Azure Key Vault
  • One API token per integration

Compliance evidence

Controls of the frameworks you follow, each with the evidence ALEN collects as work happens. Missing evidence is named, never assumed.

Developer portal

Services, APIs, docs and owners across every project, kept current from each project's model instead of a wiki nobody updates.

Cost control

Budgets per project, role and run, a usage ledger, forecasts, and routing to the cheapest model that does the job well.
